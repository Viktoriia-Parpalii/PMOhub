# PMO Hub frontend

Frontend — це React/Vite застосунок. Він завжди працює через backend API. Повна інструкція для всього застосунку є у [кореневому README](../README.md).

### Беклог і квартальна картка

У Беклозі можна відновити проєкт або операційну задачу з попереднього, навіть архівного, року в пізнішому відкритому році. Якщо під час створення виявлено збіг назви, інтерфейс пропонує цей сценарій замість створення дубля. Архівні дані не змінюються; у новому році потрібно заповнити підготовчий етап.

У модалці квартальної картки спільні кнопки біля вкладок скоупу вмикають режим перенесення або копіювання. У ньому можна вибрати одне, кілька чи всі доступні завдання, а чекбокс заголовка групи вибирає всі її доступні завдання; цільовий період задається один раз над переліком. Меню `…` залишається для групування та видалення. Групу можна перейменувати, перемістити стрілками чи розформувати. Стрілки завдання змінюють його порядок лише в межах групи, а для завдань без групи — серед верхньорівневих блоків. Нумерація 1., 2. та 1.1, 1.2 однакова у картках, таблиці, модалці й архівному перегляді. Зміни групування та порядку зберігаються після натискання «Зберегти».

У портфелі картки вирівнюються в межах рядка, а прев’ю скоупу прокручується лише коли завдань більше, ніж уміщує видима область. Якщо скоуп короткий, колесо миші прокручує сторінку. Довгі назви в редакторі переносяться на новий рядок, а прокручувані поля та віджети використовують вузькі стилізовані скролбари.

Перед перенесенням або копіюванням інтерфейс завантажує актуальну цільову картку. У масовому режимі вибрані завдання з тим самим `lineage_id` або однаковими нормалізованим текстом, числовою вагою та набором виконавців показуються окремим переліком дублів і не передаються повторно. Користувач може продовжити лише з відсутніми завданнями або скасувати всю операцію; якщо дублюються всі вибрані завдання, продовження недоступне. Копія зберігає статус і вагу вихідного завдання. Застаріла ревізія цілі потребує оновлення картки. Виконані, архівні та read-only завдання зберігають чинні обмеження.

## 1. Локально: розробка і тестування

Спочатку запустіть backend на `http://localhost:4000`. Потім відкрийте PowerShell у каталозі `frontend`.

### Налаштування

```powershell
Copy-Item .env.example .env
```

Перевірте `frontend/.env`:

```dotenv
VITE_API_URL=http://localhost:4000/api/v1
VITE_BASE_PATH=/
```

У `backend/.env` значення `FRONTEND_ORIGIN` має дорівнювати `http://localhost:3000`.

### Запуск

```powershell
npm ci
npm run dev
```

Відкрийте [http://localhost:3000](http://localhost:3000). Не змішуйте `localhost` і `127.0.0.1`, оскільки для cookies і CORS це різні адреси.

### Перевірка

```powershell
npm run typecheck
npm run test
npm run build
npm run check:bundle
```

### Типи backend API

Frontend-контракт генерується з `backend/openapi.json`. Після зміни backend route або DTO спочатку оновіть OpenAPI, а потім frontend-типи:

```powershell
Set-Location ../backend
npm run openapi
Set-Location ../frontend
npm run api:generate
npm run typecheck
```

Файл `src/api/generated/schema.d.ts` є згенерованим і не повинен редагуватися вручну.

## 2. Docker: production

Окремо запускати Dockerfile frontend не потрібно. Використовуйте кореневий `docker-compose.yml`, який запускає frontend і backend разом у різних контейнерах.

### Налаштування

Команди виконуйте з кореня репозиторію:

```powershell
Copy-Item .env.docker.example .env.docker
```

Для frontend залиште в `.env.docker`:

```dotenv
VITE_API_URL=/api/v1
VITE_BASE_PATH=/
FRONTEND_PORT=3000
```

`VITE_*` значення вбудовуються під час збирання image. Після їх зміни frontend потрібно перебудувати.

### Запуск

```powershell
docker compose --env-file .env.docker up -d --build
```

Dockerfile збирає Vite-застосунок, а Nginx віддає готові файли та перенаправляє `/api/*` до `api:4000` у внутрішній Docker-мережі.

Для первинної перевірки відкрийте `http://SERVER_ADDRESS:3000`. У production налаштуйте HTTPS reverse proxy або load balancer і відкривайте сайт через публічний домен, наприклад `https://pmohub.example.com`.

### Перевірка

```powershell
docker compose --env-file .env.docker ps
docker compose --env-file .env.docker logs -f frontend
```
